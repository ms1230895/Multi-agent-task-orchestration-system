# Summary after every feature

When a feature, roadmap step, or fix is finished, end your reply with this summary in exactly this structure. Use **bold** for the important facts.

## ✅ Feature summary: <feature name>

**What was built:** one or two sentences.

**Files changed:**
- `path/to/file` — **what changed**, and why (one line per file)

**How it works:** 3 to 5 numbered steps in plain language, as if teaching.

**Tests:** **N passed, M failed**, plus the command to rerun them.

**⚠️ Watch out:** limitations, known issues, anything left undone. Write "None" if there are none.

**🧠 Concept learned:** one idea from this feature worth remembering.

**▶️ Next step:** the next roadmap step, with the recommended model and effort from model-selection.md.

## Rules for the summary
- Bold only what matters: results, numbers, key changes, warnings. If everything is bold, nothing stands out.
- Be honest. If tests were not run or something failed, say so in bold. Never claim a success you did not verify.
- Keep it under about 25 lines.
